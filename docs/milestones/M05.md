# M05 — Games and sessions

## Objective and boundaries

Provide a public versioned game catalog plus authenticated, CSRF-protected, server-issued game sessions with strict ownership, fixed rules, server UTC expiry, hash-only secret persistence, duplicate/rate controls, and explicit lifecycle rules. M05 does not accept score/evidence submissions, verify gameplay, award XP, update personal bests, unlock characters, write leaderboards, grant rewards, add admin workflows, or implement payments/cash features.

## Assumptions and dependencies

- M04 was merged through PR #5 at `2e01742`; the merge-commit MySQL 8.4 workflow `39585348483` passed before M05 work began.
- The seven applied migrations remain immutable. `0002_game_catalog` and `0004_gameplay` already contain the necessary active-version, duration, ownership, cryptographic-hash, timestamp, mode, lifecycle, and replay-boundary columns.
- A session starts when its creation transaction succeeds. `issued -> active` occurs inside that transaction; browsers observe `active`.
- One open session is permitted per player/game/mode. Practice and ranked are independent. User-row locking serializes the policy across concurrent requests without a new partial unique index.
- Seed and nonce are independent 256-bit random base64url values, returned once and represented in persistence only by SHA-256 hashes.
- Owned expired sessions remain retrievable with `200` and `status: expired`; unknown and other-player sessions are indistinguishable `404` responses.
- Public catalog data may be cached for 60 seconds with 30 seconds stale-while-revalidate. Session creation always resolves the current database version and overrides stale discovery data.

## Acceptance criteria

- Public list/detail return active games with a published selected version/rules and active cosmetic characters while hiding draft/retired combinations.
- Ranked and practice session creation requires a live authenticated account plus signed CSRF and accepts only the mode field.
- Created sessions have unique public IDs, independent cryptographic seed/nonce material, server UTC start/expiry bounded by the selected version, and a fixed owner/game/version.
- Only hashes persist; creation delivers raw material once; retrieval, errors, and structured logs expose neither hashes nor credentials.
- Duplicate sessions, invalid mode, client version/status/time/score/XP fields, hidden games, missing authentication, and missing CSRF are rejected explicitly.
- Retrieval is owner-only, expired sessions transition safely, and valid/invalid internal lifecycle changes are enforced.
- Concurrent same-mode creation yields exactly one open session. Dedicated creation throttling returns a standardized 429.
- M06 session and score-verification ports exist without an HTTP submission route or gameplay XP effect.
- M01–M04 regressions, quality gates, OpenAPI/Postman parsing, MariaDB, and MySQL 8.4 CI pass.

## Test matrix

| Area         | Positive evidence                                                        | Negative/integrity evidence                                                     |
| ------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| Catalog      | List/detail seeded active published game/version/rules/characters        | Draft/retired game or selected version remains hidden                           |
| Creation     | Ranked and practice get unique IDs, server times, fixed version, secrets | Unauthenticated, missing CSRF, invalid mode, hidden game rejected               |
| Strict input | Exact `{ mode }` body succeeds                                           | Version, status, start/finish time, score, XP, and unknown fields rejected      |
| Secrets      | Delivered seed/nonce hashes match stored SHA-256 values                  | Raw credentials absent from persistence/logs; hashes absent from responses/logs |
| Duplicates   | Different modes coexist; replacement works after expiry                  | Concurrent same-mode requests produce one 201 and conflicts                     |
| Ownership    | Owner reads safe session fields                                          | Other player and unknown ID share 404; credentials cannot be retrieved          |
| Expiry       | Boundary time produces `expired` and permits replacement                 | Browser time/status cannot affect expiry                                        |
| Lifecycle    | Active → submitted → accepted is valid internally                        | Terminal/invalid transitions conflict; no score route exists                    |
| Rate control | Requests within configured limit succeed                                 | Next request returns `GAME_SESSION_RATE_LIMIT_EXCEEDED`                         |
| Regression   | Complete Mocha suite and production build                                | Any inherited failure blocks PASS                                               |
