# M03 — Identity and access

## Objective and boundaries

Implement registration, single-use email verification, login, cookie-backed access, refresh rotation/replay detection, logout, current-user access, account-state enforcement, and player/admin authorization. M03 does not implement profiles, password reset, gameplay, XP, leaderboards, administration workflows, email-vendor integration, or cash features.

## Assumptions and dependencies

- M02 is approved and merged at `e9d8fa9`; the seven applied migrations already contain the required identity/session/token columns and constraints.
- Local integration uses the explicitly test-scoped MariaDB schema; MySQL 8.4 remains the CI acceptance engine.
- No email vendor is approved. Verification delivery is an application interface, with a deterministic capturing adapter in tests and an unconfigured runtime adapter that never logs or exposes tokens.
- Active, email-verified accounts are required for all authenticated M03 endpoints. Pending accounts may only verify; suspended accounts are denied; deleted accounts receive the generic invalid-credentials response.
- Access and refresh credentials use host-only cookies. Production requires Secure cookies and `__Host-` names; local HTTP may explicitly disable Secure names.
- Signed, session-bound double-submit CSRF tokens protect refresh and cookie-backed logout. `SameSite=Strict` is defense in depth, not the sole CSRF control.

## Security decisions

- Passwords use Argon2id with 19,456 KiB memory, two iterations, one lane, and a 32-byte result.
- Access tokens are HS256 JWTs with fixed issuer/audience, required claims, a 15-minute default lifetime, and backing-session/account checks on every request.
- Refresh tokens contain a session lookup UUID plus 256 random bits. Only SHA-256 token hashes are stored.
- Refresh rotation locks the presented session row. Reuse of a rotated/revoked token records detection and revokes the complete family transactionally.
- Refresh lifetime defaults to 30 days; email-verification lifetime defaults to 24 hours. All durations are validated configuration.
- Unknown email and wrong password have the same login response and both execute password-hardening work.

## Acceptance criteria

- Registration normalizes identity fields, rejects invalid/weak input, handles database uniqueness races, and stores no plaintext credential or token.
- Email-verification tokens are hashed, expire, activate the account once, and reject replay.
- Login enforces verification/status policy without email enumeration and sets hardened cookies without returning tokens in JSON.
- Access authentication verifies JWT claims plus live database session/account state.
- Refresh rotates transactionally, detects old-token replay, revokes families, handles expiry, and is safe under concurrent requests.
- Logout revokes immediately, clears cookies, and is idempotent.
- Signed CSRF validation and dedicated registration/login throttling are demonstrated.
- Player/admin allow/deny behavior is demonstrated through the minimal authorization probe.
- Existing M01/M02 behavior remains passing on MariaDB and MySQL 8.4.
- OpenAPI, Postman, security documentation, report, and M04 handoff reflect actual behavior.

## Test matrix

| Area          | Positive evidence                                    | Negative/security evidence                                                     |
| ------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| Registration  | Normalized account and Argon2id hash persist         | Weak input, normalized duplicates, and concurrent uniqueness races fail safely |
| Verification  | Single token activates account                       | Unknown, expired, and replayed tokens fail generically                         |
| Login         | Verified active account receives hardened cookies    | Unknown/wrong credentials match; pending/suspended/deleted policy enforced     |
| Access        | Valid JWT plus live session returns current user     | Invalid/expired JWT, revoked session, and changed account state fail           |
| Refresh       | Session row locks, rotates, and links replacement    | Replay, expiry, and concurrent refresh revoke or reject safely                 |
| Logout        | Current session revoked and cookies cleared          | Repeated logout remains successful; missing CSRF with cookies fails            |
| Authorization | Admin probe allows admin                             | Player denied; suspended account denied immediately                            |
| Secrets       | Only hashes persist and tokens stay out of JSON/logs | Plaintext scans and response assertions detect disclosure                      |
| Regression    | Full Mocha suite and build                           | Any existing M01/M02 failure blocks PASS                                       |
| Engines       | MariaDB local and MySQL 8.4 CI                       | Either unverified engine is an acceptance gap                                  |
