# M02 — Data model and migrations

## Objective and boundaries

Create the normalized Release 1 schema, a checksum-verified migration runner, safe rollback/status commands, and deterministic non-production seeds. M02 does not add business HTTP APIs, authentication behavior, score verification logic, workers, payments, staking, or cash rewards.

## Decisions and assumptions

- XAMPP MariaDB 10.4 is the local engine; MySQL 8.4 is the selected production/CI compatibility target.
- Internal primary keys are unsigned big integers. Publicly addressable records also use application-issued UUID strings.
- All timestamps are UTC `DATETIME(6)` values. Database connections set UTC explicitly.
- The approved PRD resolves the earlier progression wording: gameplay XP is `floor(validated score / 10)` and level is `1 + floor(total XP / 500)`. Policies are versioned so historical results retain their interpretation.
- Ranked score is derived only from a verified result. Raw client claims and replay events are stored separately and never become authoritative by schema placement.
- Weekly periods, grace deadlines, best entries, deterministic tie fields, finalized placements, and idempotent reward grants are distinct records.
- XP ledger and administrator audit records are append-only. Corrections use new adjustment records.
- Deterministic seeds contain catalog/configuration fixtures only, not usable credentials or production accounts.
- MySQL and MariaDB implicitly commit DDL. The runner serializes migrations, verifies checksums, records only completed migrations, and provides explicit down scripts; it does not claim impossible transaction-wide DDL rollback.

## Dependencies

- Approved and merged M01 at commit `947d772`.
- Node.js 24+, npm 11+, and the existing `mysql2` promise pool.
- An isolated database whose name visibly contains `test` for destructive integration tests.
- MySQL 8.4 CI confirmation is required in addition to local MariaDB results for full cross-engine acceptance.

## Acceptance criteria

- Fresh migration reports all versions pending, applies them in order, and records checksums.
- A repeated up run is a no-op; modified applied migrations are rejected.
- Status accurately distinguishes pending/applied versions.
- Down removes the requested newest versions, all-down leaves no business tables, and reapply succeeds.
- Foreign keys, unique keys, checks, ranking indexes, and idempotency constraints are demonstrated.
- Append-only triggers reject mutation of XP and audit history.
- Seed execution is deterministic and repeat-safe, and refuses production or non-development/test databases.
- A forced DML failure rolls back every write in its transaction.
- Existing M01 health/configuration/security tests remain passing.
- Formatting, lint, typecheck, complete tests, build, dependency audit, MariaDB verification, and MySQL 8.4 CI are evidenced.

## Test matrix

| Area           | Positive path                                      | Failure/security path                                           |
| -------------- | -------------------------------------------------- | --------------------------------------------------------------- |
| Loader         | Ordered SQL files parse with up/down sections      | Duplicate versions, missing sections, and checksum changes fail |
| Status/up      | Fresh pending → applied; repeat applies zero       | Failed SQL is not inserted into migration history               |
| Down/reapply   | One-step and all-step rollback; fresh reapply      | Unsafe database/production rollback is refused                  |
| Identity       | Unique user and token records                      | Duplicate email/username/token and invalid role/status fail     |
| Gameplay       | Valid session, events, submissions, verified score | Invalid FK/check and duplicate verified result fail             |
| Progression    | XP event/unlock and versioned policy persist       | Duplicate idempotency and update/delete of XP history fail      |
| Competition    | Period, best entry, placement, reward persist      | Duplicate period entry/placement/reward fails                   |
| Administration | Moderation/audit records persist                   | Audit update/delete fails                                       |
| Seeds          | Two runs retain identical catalog counts/content   | Production and ambiguous database names are refused             |
| Transactions   | Multi-write operation commits                      | Forced exception rolls back all writes                          |
| Engines        | MariaDB 10.4 local and MySQL 8.4 CI                | Any unverified engine remains an acceptance gap                 |
