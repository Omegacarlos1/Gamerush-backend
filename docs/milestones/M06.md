# M06 — Score verification and anti-cheat

## Objective and boundaries

Accept bounded untrusted endless-runner evidence for an owned ranked session, deterministically replay it against the issued seed and immutable rules, persist one authoritative score, and grant gameplay XP exactly once. M06 excludes characters/unlocks, leaderboards, achievements/rewards, admin review, payments, staking, wallets, and cash features.

## Assumptions and dependencies

- M05 was approved and merged through PR #6 at `86ba28c`; its MySQL 8.4 workflow run `39587769907` completed successfully for `d805966`.
- Migrations `0001`–`0007` remain immutable. `0003_progression` and `0004_gameplay` already support the required transaction, uniqueness, evidence/result separation, and append-only XP effect.
- `runner-evidence-v1` and `runner-score-v1` are the only accepted contract/rules pair.
- Structurally valid anti-cheat rejections are terminal. Malformed transport input persists nothing; server/policy failures roll back and are retryable.
- Practice score submission is rejected without persistence or rewards.
- A calculated zero-XP result is an explicit no-op for the positive-only XP ledger.

## Acceptance criteria

- Strict bounded evidence, ordered events, credential/version binding, deterministic replay, server finish time, and authoritative score formula are enforced.
- Authenticated CSRF-protected submission requires an idempotency key and an owned active unexpired ranked session.
- Accepted score, events, submission, gameplay XP, cached progression, and session state commit atomically once.
- Safe terminal rejection codes persist without exposing verifier detail; private evidence never crosses a response/log boundary.
- Identical retries return the original result; payload drift and subsequent submissions conflict.
- Concurrent identical/conflicting submissions serialize to at most one score and XP effect.
- Owner-scoped retrieval returns only safe processing/result fields.
- Five forced persistence-stage failures roll back every authoritative effect and retain retryable session state.
- OpenAPI, Postman, architecture/security/progression/session docs, complete regression tests, and both database-engine evidence are supplied.
