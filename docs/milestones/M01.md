# M01 — Foundation and developer experience

## Objective and scope

Establish the strict TypeScript/Express backend, safe configuration and HTTP defaults, XAMPP MariaDB connectivity, health API, test harness, documentation, and CI starter. No business modules, tables, migrations, authentication, scoring, XP, rewards, Socket.IO, payments, or frontend work belong to M01.

## Assumptions and dependencies

- PlayRush is the working backend name even though the PRD filename/title still says GameRush.
- Local development uses XAMPP MariaDB; production remains MySQL.
- Node 24+ is the supported runtime baseline.
- The health endpoint represents readiness as well as process health and therefore checks the database.
- MariaDB must be running and an isolated database whose name contains `test` must exist for the full local test suite.
- M01 performs no schema migrations and no database writes in tests.

## Acceptance criteria

- Strict TypeScript Express project with separate app factory and startup.
- `/api/v1/health` returns 200 only when the database probe succeeds.
- Database failure returns safe 503; unknown routes return standardized 404.
- Environment validation fails before startup and rejects unsafe production settings.
- Request IDs, structured/redacted logs, controlled CORS, Helmet, rate limits, and request size limits are enabled.
- Mocha, Chai, and Supertest cover success, failure, negative, and secret-leakage paths.
- Format check, lint, typecheck, full tests, build, and dependency audit pass.
- README, architecture, OpenAPI, Postman, report, CI, and M02 handoff exist.

## Test matrix

| Area          | Positive evidence                        | Negative/security evidence                                                |
| ------------- | ---------------------------------------- | ------------------------------------------------------------------------- |
| Configuration | Valid MariaDB config parses              | Missing DB name and unsafe production config fail without echoing secrets |
| Health        | DB probe success returns 200             | DB exception becomes generic 503 with request ID                          |
| Routing       | Versioned health route responds          | Unknown route returns standardized 404                                    |
| HTTP defaults | Security headers and request ID present  | Disallowed CORS, oversized body, invalid JSON, and excess rate rejected   |
| Logging       | JSON logger emits records                | Password, token, and authorization fields are redacted                    |
| Database      | Real `playrush_test` `SELECT 1` succeeds | Test guard rejects a database name not visibly test-scoped                |
| Quality       | Format, lint, typecheck, tests, build    | Any non-zero command blocks PASS                                          |
